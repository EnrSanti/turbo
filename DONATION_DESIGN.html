Work donation without grid synchronisation

Design note for Turbo 1.2.8 barebones (restart branch) · 2026-11-19 · proposal, not implemented. Line numbers refer to include/barebones_dive_and_solve.hpp as of today.
In one paragraph. Today the restart repartitions the work globally: every block stops, harvests its open nodes under grid.sync() (S1), block 0 resets the round, and everyone restarts after a second grid.sync() (S3). The barrier is needed only because the reset is non-monotone (the counter goes back to B, the flag and idle_blocks go back to 0). Work donation replaces this global step by local, one-at-a-time transfers: an idle block posts a request in its own slot; any busy block, at the safe point it already has at the end of each node, claims the slot with one CAS, copies its shallowest open node into it, and marks that node as given away. Nothing is ever reset, so there is no barrier, no round, no restart threshold and no cooperative launch. All shared data is either a lattice element updated monotonically (bound, EPS counter) or a slot owned by exactly one block at a time.

The victim's stack is never read by another block: the donor copies from its own stack into the receiver's slot. That is the main difference with stealing (thief reads the victim), and it removes all version/ABA problems.

3. The slot protocol

Each slot is owned by its receiver (slot index = blockIdx.x of the idle block), so no allocation is needed and at most one request per block exists. CLAIMED → FILLED is a promise: a donor claims only when it has already chosen the level to give, so filling cannot fail.

3.1 Receiver (block r becomes idle)

// thread 0, when its subproblem is finished and next_subproblem is exhausted
active.fetch_sub(1);                         // I hold no work any more
slot_state[r].store(REQUESTED, release);
requests.fetch_add(1);
loop:
  s = slot_state[r].load(acquire);
  if (s == FILLED) break;                    // work arrived
  if (s == REQUESTED && active.load() == 0) -> leave the kernel loop (all idle, nothing in flight)
  if (stop) -> leave
  __nanosleep(backoff);                      // ~1 us: do not hammer L2 while others work
__syncthreads();
// all threads: rebuild the donated node, same code as today's C' (l.939-975) with src = slot r
slot_store[r] -> store;  embed slot_dec[0..k-1].current();  embed slot_dec[k].children[1];
strategy = slot_root_strategy[r]; next_unassigned_var = slot_root_next_var[r];
thread 0: slot_state[r].store(EMPTY);        // payload consumed, slot reusable
// continue as a normal subproblem with s_bits = 0 (no dive); root_store is taken at depth 0 as today

3.2 Donor (busy block, at the end of every node)

Placed where the restart check is today (l.1225): the last split or backtrack is embedded but not propagated, the stack is consistent, nothing is half-done.

// thread 0
if (requests.load(relaxed) > 0) {                       // same cost as today's restart_flag poll (l.1610)
  k = shallowest level with decisions[k].current_idx == 0 && !donated[k] && k <= depth-1-G;
  if (k exists)
    for r in slots, starting at (blockIdx.x+1) mod B:    // spread donors over receivers
      if (slot_state[r] == REQUESTED && CAS(slot_state[r], REQUESTED, CLAIMED)) { won = true; break; }
  if (won) { requests.fetch_sub(1); active.fetch_add(1); donated[k] = true; }   // +1 on behalf of r
}
__syncthreads();
if (won) {                                               // all threads: same code as today's harvest copy (l.1288-1299)
  root_store -> slot_store[r];   decisions[0..k] -> slot_dec[r];
  thread 0: slot_k[r] = k; slot_root_strategy[r] = snapshot_root_strategy; slot_root_next_var[r] = snapshot_next_unassigned_var;
  __threadfence(); __syncthreads();
  thread 0: slot_state[r].store(FILLED, release);
}

3.3 The donor never explores what it gave away

Backtracking follows ropes (l.1161): the target depth d means “go to level d-1 and take its right child”. The donated level must be skipped, but current_idx must not be changed: the donor is still inside the left subtree of level k, and every redescend re-applies decisions[i].current() (l.1196), so setting current_idx = 1 would move it into the given-away subtree. Instead, the backtrack follows the rope past donated levels:

d = decisions[depth-1].ropes[decisions[depth-1].current_idx];       // as today
while (d != -1 && donated[d-1]) d = decisions[d-1].ropes[1];        // its right subtree belongs to someone else
// push_decision (l.458): donated[depth] = false;  (a re-pushed level is a new decision)

The rope of level d-1's right child (ropes[1]) is exactly where the donor would have gone after finishing that subtree, so the donor continues as if the subtree had been explored and found empty.

4. Termination

active counts the blocks that hold work, plus donations in flight: a donor adds 1 for its receiver right after winning the CAS, while it is itself still counted, so active never touches 0 while a transfer is in progress. Hence:

  • active == 0 ⇒ no block holds work and no slot is CLAIMED/FILLED ⇒ the search is complete.
  • active == 0 is stable: nobody holds work, so nobody can donate, so it never goes back up.
  • Each idle block detects it on its own while polling its slot; no block waits for another to leave.

This is the shared-memory form of credit/weight-based distributed termination detection (Mattern 1987). If one prefers only monotone counters, the same predicate is finished == B + given with two increasing counters packed in one 64-bit word (one fetch_add, atomic snapshot).

Node identity: decisions, not bits. The donated node is described by its actual decisions (variable + child domain per level), exactly like today's harvest items (snap, k, c). It must not be identified by a left/right bitstring: with a tighter bound, propagation changes and the branching heuristic may pick another variable at the same depth, so the same bits would denote a different node and coverage would break.

Expected effect: no waiting for a threshold, no stop of busy blocks. Idle time should remain only at the very end, when the remaining subtrees are smaller than what is worth donating (the same tail limit the restart has). The gap G (do not donate a level too close to the current node) is the one tuning knob; the receiver's replay (~0.3 ms) is the minimum size a donated subtree should have.

8. Open points

  • Best bound. The barrier recomputed the exact minimum (l.1347), repairing the racy meet of appx_best_bound. Without barriers only the monotone meet remains; an atomic fetch_min would make it exact (a change to upstream code: to be decided separately).
  • Which level to donate. Shallowest open level (largest subtree) is the classic choice (Rao & Kumar; Schulte). A confidence-based choice (Chu, Schulte & Stuckey) is a later refinement.
  • EPS size. With dynamic balancing the initial 213 subproblems may be reducible (fewer dives, less redundant_dive_nodes): an experiment.
  • Request discovery. A slot scan (≤ 216 loads) only when requests > 0; a monotone ticket queue (two increasing counters) is an alternative.
  • Before code: run -restart 1 and -restart 5; if idle already drops to ~0 % with negligible overhead, the gain left for donation is the stop of busy blocks only.

9. Where this has been done

Short answer: receiver-initiated donation with polling at safe points is an established technique on CPUs (parallel DFS since the late 1980s, work stealing with private deques in 2013), and donation/stealing between persistent blocks has been studied on GPUs (rendering, branch-and-bound). I did not find a GPU constraint solver that balances its search tree between blocks this way, nor one that frames it with lattice-monotone shared state.
