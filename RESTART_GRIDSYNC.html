Restarts entirely on the GPU: one round loop, two grid syncs

Turbo 1.2.8, barebones (include/barebones_dive_and_solve.hpp). Rev. 5, 2026-11-18: theory + the implementation as it is in the code (implemented 2026-11-17, uncommitted, every change tagged //RESTART in barebones_dive_and_solve.hpp, config.hpp, config.cpp, statistics.hpp). Line numbers refer to the current, modified files. Continues RESTART_STRATEGY.pdf (restart type A, load balancing). Rev. 4 (design only) is replaced by this document.

0. Summary

  1. Rounds inside one cooperative kernel. Round 0 is today's EPS search. A block that runs out of work counts itself idle and waits in grid.sync(). When enough blocks are idle, a busy block raises a global flag; every busy block stops at the end of its current node. All blocks meet at S1, the busy ones publish their open nodes, block 0 resets the round at the same time, all meet at S3, and the next round starts on the published nodes (§2–§4).
  2. Open nodes of any depth are fixed 8-byte items {snap, k, c} = "path of block snap down to level k, then child c", pointing into a per-block snapshot (copy of root_store + decision stack). Rebuilding an item is the barebones backtrack (§5).
  3. Too few items are split by one uniform depth s = smallest with n·2s ≥ T, T = restart_subfactor · B: index j → item j >> s, dive on the low s bits. Steps D and E of the dive are unchanged (§6).
  4. Without -restart (default 0) the kernel takes the old path: normal <<<…>>> launch, the round loop runs once and leaves before any barrier.
  5. Side effects of the work: an upstream race in step E fixed (counter moved backwards, §7.1; also affects the non-restart path) and a new statistic tree_nodes that counts each node of the search tree once (§8), used to prove that the restarts neither lose nor duplicate work.

1. Theory

1.1 The search tree and EPS

Barebones explores a binary tree: at a node the split strategy picks a variable and two complementary children L = children[0], R = children[1] (for intervals x ≤ m / x ≥ m+1, so R = ¬L at that node). Embarrassingly Parallel Search (Régin, Rezgui, Malapert, CP 2013) cuts the tree at a fixed depth D into 2D subproblems; Turbo's variant identifies subproblem j with the bit path of j (bit = left/right at each dive level, l.1008) and hands indices out with one atomic counter (l.1229). In round 0, D = subproblems_power = ⌈log2(30·B)⌉ = 11 for B = 40, i.e. 2048 subproblems.

The dyadic structure is what step E uses: if the dive reaches a leaf (failed or solved) with rd bits left, all indices of the aligned block [⌊j/2rd⌋·2rd, (⌊j/2rd⌋+1)·2rd) share that leaf, and the counter jumps to the end of the block.

The weakness measured on accap (2026-11-11 baselines): EPS has no work stealing, subproblem sizes are very uneven, so the last few subproblems keep a few blocks busy while the rest is idle (61 % idle at 2000 s). A restart re-splits the work that is still open among all blocks.

1.2 The open frontier of a DFS stack

Let the stack of a block have entries 0…d−1; entry k stores the decision at level k and current_idx ∈ {0,1}, the child it is in. Write Pk = dec[0..k).current() for the path above level k.

Proposition 1 (frontier partition). Stop a depth-first, left-first search at a point where the current node Pd has been reached but not propagated. Then the unexplored part of the block's subproblem is exactly the disjoint union of
  • Pk ∧ Rk for every level k with current_idx = 0 (right branch never started), and
  • the current node Pd−1 ∧ children[current_idx]d−1.
Proof sketch. Walk from the root to the current node. At a level with current_idx = 1 the search came back from Lk: by DFS order that subtree was explored exhaustively, so nothing open is in it. At a level with current_idx = 0 the search is still inside Lk; Rk is untouched. Every node not on the path lies in exactly one of these sibling subtrees or below the current node, and siblings are disjoint because Rk = ¬Lk. ∎

This is Lecoutre et al., "Recording and minimizing nogoods from restarts" (JSAT 2007), Prop. 1, seen from the other side: the levels with current_idx = 1 are exactly the negative decisions of the branch, and each gives the nld-nogood Pk ∧ Lk (the refuted left subtree). Our restart keeps the same tree (same order, only re-split), so these nogoods need not be stored: they are simply not in the open set. Nogoods would be needed only for a restart that changes the tree (type B in RESTART_STRATEGY.pdf).

Branch-and-bound. In optimisation the search does not stop at a solution, so "explored Lk" means "no solution better than the bound in force while Lk was explored". The bound only decreases, so the refutation stays valid in every later round, provided the next round uses a bound at least as tight. The reset computes the exact bound (§4, step 1).

Across blocks, the subproblems of a round are disjoint, so the union of all frontiers at S1 is exactly the unexplored part of the whole problem (indices not handed out yet do not exist at that moment: see §3.1).

1.3 Splitting items: dyadic alignment

Proposition 2. With n items and a uniform depth s, item i owns the indices Ii = [i·2s, (i+1)·2s). For any j ∈ Ii and any rd ≤ s, the skip target ((j >> rd)+1) << rd is either inside Ii or equal to (i+1)·2s. Proof. Ii is a union of aligned blocks of size 2rd because 2rd divides 2s. ∎

So E never skips into, or out of the middle of, another item: each item is split exactly as EPS splits the root. Step D and E need only remaining_depth = s instead of subproblems_power. Round 0 is the case n = 1 (the root), s = subproblems_power.

1.4 Grid barriers and the one-writer rule

cooperative_groups::this_grid().sync() is a barrier for all threads of all blocks and a device-wide memory fence; it is legal only with cudaLaunchCooperativeKernel and all blocks co-resident (a block not yet scheduled could never arrive). Between two barriers the code obeys one rule: every datum is either written or read in the window, never both, and each written datum has a single writer or is updated atomically. Then no further synchronisation is needed inside the window, and after the next barrier every block sees all the writes. §4 lists the data.

A value that decides whether a block leaves the round loop must be grid-uniform: if one block leaves while another enters the next grid.sync(), the GPU hangs. Hence all exit decisions are taken on values written before S3 and read after it (host_stop, n), never on the per-block shared stop.

1.5 Lost updates: meet is not atomic

ZLB::meet / ZUB::meet on atomic_memory_grid are load / compare / store: each access is atomic, the read-modify-write is not. Two concurrent writers can lose an update. Consequences in the code:

  • appx_best_bound (l.1541) can be worse than the best bound found (as the name says). Harmless for soundness; fixed exactly at every restart (§4, step 1).
  • next_subproblem.meet(x) in step E can move the counter backwards (§7.1). That is a real bug: indices handed out twice. Replaced by an atomic fetch_max.

3.1 Why the subproblem loop needs no !restart

A block counts itself idle only if it left the loop with neither stop nor restart, i.e. because subproblem_idx ≥ num_subproblems. The counter only grows during a round, so once any block is idle the counter is exhausted, and the flag can only be raised after that (§3.2). Hence a block that breaks out of F because of the restart gets, in step G, an index ≥ num_subproblems and leaves the loop by itself. Guarding G with !restart without changing the loop condition would make the block explore its current subproblem again while its open nodes are also published. A restart that does not come from idle blocks (timer, forced debug restarts) would need !restart in both places; none is implemented.

3.2 Trigger: raised by a busy block, in propagate()

Change from rev. 4: the design had the idle block raise the flag when it incremented the counter. Implemented instead (l.1584–1601), once per node in thread 0 of every block:

if(restart_enabled && !restart) {
  if(restart_flag != 0) restart = true;                                // someone raised it
  else if(idle_blocks >= restart_threshold && (restart_max == 0 || st_restarts < restart_max)
          && now - round_start_ns >= restart_min_ns) {
    if(restart_flag.compare_exchange_strong(0, 1)) raise_ns = now;     // one winner records the time
    restart = true;
  }
}

Reason: an idle block is already on its way to grid.sync() and will not look again. If it found now − round_start < Tmin, nobody would re-check later and the round would never restart. The busy blocks run nodes continuously, so the condition is re-evaluated until it holds. restart_threshold = max(1, ⌈P·B/100⌉) (l.130). The CAS makes the raise and its timestamp single-writer. The shared copy restart is read by all threads after the __syncthreads() that follows propagate(), so the whole block takes the same branch, as for stop. Unlike stop, it does not set exhaustive = false.

The dive (D) and the rebuild (C') also call propagate() and may see the flag, but they are not interrupted: the block finishes the dive, enters F, and breaks at the end of the first DFS body. So at S1 nobody is in a dive or a rebuild, and a single snapshot buffer per block suffices.

Deadlock rules, as enforced in the code
  1. Every path out of the subproblem loop reaches S1: no return inside; the early exits (failed root, solved subproblem, E skip) go through G and the loop head.
  2. The round loop ends only on host_stop and n, written by block 0 before S3 and read after it.
  3. stop_after_n_nodes is per block: with restarts it now also sets the global unified_data.stop (l.1580), so every block stops and block 0 reads host_stop = true.
  4. Idle blocks wait only in grid.sync(), never spin on a counter.

5. Open nodes as items

5.1 What is open when a block stops

The restart test is at the end of the DFS body (l.1205), after III/IV, so: root_store has always been taken (first iteration at depth 0); the last split or backtrack has embedded L or R without propagating it, so the current node is unexplored. This is the precondition of Proposition 1. If the block saw stop as well, open_subproblem = false: nothing is published, the search is ending anyway. A block whose subtree ended at the same node (fail at root, solved) leaves F earlier and also publishes nothing.

5.2 Snapshot and harvest (l.1260–1317)

struct FrontierItem { int snap; unsigned k : 31; unsigned c : 1; };   // l.99, 8 B
// in BlockData (l.211): allocated once by allocate_snapshot() when -restart > 0
abstract_ptr<VStore<Itv, global_allocator>> snap_store;              // copy of the root store
vector<LightBranch<Itv>, global_allocator> snap_dec;                 // sized like decisions
int snap_depth, snap_root_strategy, snap_root_next_unassigned_var;
// in GridData: items (B × 1024), n_items[2], restart_flag, idle_blocks, ... (l.503–530)
  1. If decisions has grown (push_decision doubles it), thread 0 resizes snap_dec.
  2. root_store->copy_to(group, *snap_store); the threads copy decisions[0..depth) field by field (var, children, ropes, current_idx), strided.
  3. Thread 0: snap_depth, root strategy and next variable (the values the backtrack restores at depth 0, from snapshot_root_*); counts pending = #{k : current_idx = 0}; reserves m = pending + 1 slots with one n_items[round&1].fetch_add(m); writes (k, 1) for each pending level, bottom-up, then (depth−1, current_idx of depth−1).

Quota items_per_block = 1024, so n ≤ B·1024 and items never overflows. If pending + 1 > 1024 (not expected: it needs more than 1023 pending right branches on one stack), the block keeps the 1023 shallowest pending right branches and, as last item, the child it is in at the level of the last kept one (c = 0): it covers every deeper open node and re-explores some refuted parts. Nothing is lost; counted in restart_truncated_blocks.

One snapshot and one item array suffice: they are written only between S1 and S3 and read only during a round. Once an item is rebuilt, its whole prefix is inside the new root_store, so at the next restart the block snapshots that store and a short stack: paths never accumulate across rounds. The dive decisions are not on the stack (they are in root_store already).

This is the backtrack code reading another block's snapshot. No propagation in C' itself: the first propagate() of D (or of F if s = 0) computes the fixpoint of the rebuilt node. The dive inside an item continues with the item's own search strategy; the bits only choose left/right. The fixpoint-engine reset is required only with TURBO_NO_ENTAILED_PROP_REMOVAL OFF (a rebuilt item comes from another part of the tree, its entailed set is different); with the option ON (default, and in build/gpu-release) it is compiled out, as before.

6. Splitting: one uniform depth

After S3, with n items and T = restart_subfactor·B (1200 with the defaults on 40 blocks), every block computes the smallest s with n·2s ≥ T (loop, capped at 40), num_subproblems = n·2s; index j → item j >> s, dive bits = low s bits of j.

Round 0 keeps its own code path for C (copy of the global root) and its own s = subproblems_power, so it is bit-for-bit the old search; rounds ≥ 1 use C'. Extra bits on a small item are cheap: E skips the dead branches as soon as the dive meets a leaf.

7. Changes outside the restart logic

7.1 Bug fix: the E skip could move the counter backwards (l.1043–1050)

// before  while(grid_data->next_subproblem.meet(ZLB(next_subproblem_idx))) {}
// now     grid_data->next_subproblem.atomic().fetch_max(next_subproblem_idx, relaxed);

meet loads the counter, compares, stores. If between the load and the store other blocks take indices with atomic()++ past next_subproblem_idx, the store writes a smaller value: those indices are handed out a second time (duplicated work, and duplicated eps_solved_subproblems/nodes counts). Found while verifying the restarts; fetch_max is a single atomic and monotone. This also changes the non-restart path.

7.2 stop_after_n_nodes stops the grid (l.1580)

With -restart, reaching the node limit sets unified_data.stop, so the exit is grid-uniform (deadlock rule 3). Without -restart the old per-block behaviour is kept.

7.3 Solved-subproblem count (l.1215–1220)

eps_solved_subproblems is incremented only if !open_subproblem: a subproblem interrupted by a restart is not solved; its remainder is counted by the items that finish it.

9. Correctness and verification

  • Completeness: at S1 every unexplored node is in exactly one item (Prop. 1 per block, disjoint subproblems across blocks, counter exhausted); each item is partitioned by the uniform split (Prop. 2); E skips only subtrees whose root is a leaf; truncation only enlarges items.
  • Optimality: refutations are relative to bounds that only decrease; the next round starts with the exact minimum.
  • Termination: every busy block finishes at least its current node before stopping, and each restart needs Tmin and at least ⌈P·B/100⌉ idle blocks; -restart_max bounds the number of restarts. A round with no busy block publishes n = 0 and everyone exits.
  • No deadlock: §3.2 rules; exit values are grid-uniform.
