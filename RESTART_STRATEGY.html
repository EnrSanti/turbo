Restarts for Turbo barebones: the strategy

Illustrated summary of NOGOOD_RESTART_DESIGN.pdf (13 Nov 2026) + validation plan. Proposal only: no code was modified. Line numbers: include/barebones_dive_and_solve.hpp. 16 November 2026.
In one sentence. When too many blocks are idle, stop the kernel, collect the open nodes (the unfinished parts of the tree, which are already written in the blocks' decisions stacks), and relaunch with those nodes as a new, finer work queue, carrying the exact best bound. Nothing already explored is redone; only the propagation along the current paths is recomputed (≈ 6 ms per block on accap).

1. The problem we want to fix

EPS cuts the tree into 2048 subproblems handed out by one atomic counter, with no work stealing. On accap_a3 all 2048 subproblems have been handed out by ~480 s (the first block goes idle at 476–520 s depending on the run); from then on a block that finishes its subproblem has nothing left and stays idle, while the blocks holding the hard subtrees keep going, and those cannot be split further.

2. Where the remaining work is: the open frontier

The stack in the code: block_data.decisions

Each block has its own stack decisions (a vector of LightBranch in global memory, l.135) and its height depth (l.138). Entry decisions[k] is one binary split, pushed by push_decision (l.364–404), and holds:

fieldmeaning
varthe variable that was split (l.367)
children[0], children[1]the two branches L and R as absolute intervals of var, R = ¬L (l.371–393; e.g. SPLIT: L = [lb, mid], R = [mid+1, ub])
current_idxwhich branch the block is in now: −1 just pushed (l.368); 0 after next() applied L (l.925); 1 after a backtrack applied R (l.980). next() = children[++current_idx] (light_branch.hpp:31–34)
ropes[0], ropes[1]where to backtrack when the current branch is finished (l.402–403, used at l.938): ropes[0] = k+1 = "come back to this level and take R"; ropes[1] = the parent's rope = the nearest ancestor that still has an R pending (−1: the subproblem is finished)

The current node is not an entry: it is the store obtained from root_store by applying children[current_idx] of every entry decisions[0 … depth−1] (exactly what the backtrack recomputation does, l.955–980). The dive decisions that led to the subproblem are not on the stack (l.805–806: "we do not record the decisions when diving"); their effect is the snapshot root_store, taken at depth 0 after the root fixpoint (l.900–901).

Rule (any block, any depth): every entry with current_idx = 0 gives one open node (the current branches below it, then its R), plus one open node for the current path. Entries with current_idx = 1 give nothing. "Refuted" in branch-and-bound means "no solution better than the bound in force", so these are valid under z ≤ ub − 1, the bound the next round starts with.

State when stop arrives: the kernel is not killed. The host cannot interrupt a running kernel; it only sets the flag unified_data.stop (wait_solving_ends, l.530). Each block polls it once per node: thread 0 copies it into the shared stop at the end of propagate (l.1193–1197). Between propagate (l.896) and the end of the loop body (l.998) there is no stop check, so:

  1. the running node always completes its fixpoint (the fixpoint stops on iprop.is_bot() or quiescence, never on stop);
  2. the block then does one more step without a fixpoint: on a non-leaf, split pushes a new entry and next() applies L (l.913–925, new top entry with current_idx = 0); on a leaf, it jumps along the rope, restores root_store and next() applies R (l.938–980);
  3. only then while(!stop) (l.868) exits; step G does not take a new subproblem (if(!stop), l.1011) and the block ends.

Latency: at most one node (accap 1000 s: 157 µs on average, 3.7 ms worst case). The extra push is harmless: it only cuts the current, unexplored node into L and R, both open, so the harvest gets 2 items instead of 1 (or pops that fresh entry to get the parent back as one item). Nothing explored is lost and nothing is duplicated. Two edge cases: depth = −1 after the last rope (the subproblem had just finished: nothing open), and a block that had just taken one of the last indices and is still in its dive (no stack yet: the open node is its whole subproblem index).

Full open set at restart time = { for each busy block: its pending Rᵢ (entries with current_idx = 0) and its current node }. Nothing else: the restart is triggered only when blocks are idle, i.e. never at full occupancy, and a block can go idle only when its next index is ≥ 2048 (l.748, l.1013), so by then every subproblem has been handed out. Each subproblem is therefore either finished or held by a busy block (any index, not necessarily a late one). Finished subproblems and refuted L subtrees are simply absent: the open nodes are the complement of the nld-nogoods, so no nogood needs to be stored for this kind of restart.

Size on accap: one open node per entry with current_idx = 0, plus one per busy block. The measured average path at a backtrack is ~29 entries (accap, 2026-11-10), so the upper bound is 40 × ~29 ≈ 1,000 open nodes, i.e. ≤ ~25 per block, close to the 30 per block that EPS targets at the start. In practice fewer: only the busy blocks count (36 with X = 10%, 24 at the end of the 1000 s run), and only the entries with current_idx = 0.

3. The restart round, step by step

  1. Run. Round 0 is today's barebones. In later rounds a subproblem is a queue item (a literal path) instead of an 11-bit index: copy the root store, embed the item's literals, propagate once, then do the normal DFS with an empty stack.
  2. Trigger. When the number of finished blocks reaches X% of 40, set unified_data.stop. Never at full occupancy: a block can only finish after the counter passed 2048, so at that point all subproblems are handed out. On accap the 1000 s run crosses 10% idle at ~500–550 s.
  3. Drain. Each block notices stop at the end of its current node (l.1193–1197), finishes that iteration (one split or one backtrack, see "State when stop arrives" in section 2) and leaves its loops, within one node (≤ 3.7 ms on accap). No node is cut short. Its decisions, depth, subproblem_idx and root_store are in global memory (heap), so they survive the kernel.
  4. Harvest. Read the open nodes of the busy blocks' stacks (section 2). Recompute the bound exactly from the per-block best_bound (as reduce_blocks does, l.1260–1282), not from appx_best_bound, whose racy meet can hold a worse value.
  5. New queue. Items = literal paths; the root gets z ≤ ub − 1. Hand out the shallowest items first (biggest subtrees), so the long ones start early. Then relaunch; repeat whenever idle reaches X% again.

What is kept and what is lost

keptrecomputed / lost
  • every finished subproblem and refuted L subtree (never revisited)
  • the pending R siblings (they were not started, nothing to lose)
  • the best solution: each block's best_bound/best_store, reduced, enters the next round as z ≤ ub − 1
  • the propagated store along each current path: one fixpoint per item, exactly like a barebones backtrack (≈ 240 µs, 20.4 rounds on accap)
  • ≤ ~25 items per block → ≤ ~6 ms per block per restart: negligible against 1000–2000 s
  • the one split or backtrack each block applies after stop is not propagated; it is recomputed with its item (no explored work is lost)

4. Two kinds of restart (do A first)

A. load-balancing restartB. heuristic restart
treesame tree, same variable/value order, only re-splitdifferent tree (new order, randomization, new EPS split)
what carries the explored workthe open frontier (section 2)nogoods: the frontier's paths mean nothing in a new tree
new propagatornoneone "branch" propagator in the same fixpoint
targetsend-of-run idle (61% on accap 2000 s)bad early decisions (heavy-tail behaviour)
Why nogoods are not needed for A. Inside one DFS the search never re-enters a refuted subtree, and between blocks subproblems are disjoint, so a nogood from block A contradicts block B's prefix anyway. Nogoods pay off only when the next run explores a different tree (jsat07 §4), i.e. only for B.

Points to decide before coding.
  • X (trigger threshold) and whether to restart repeatedly (each time idle reaches X% again) or at most N times.
  • Host round-trip vs. in-kernel. A second kernel launch is simpler (no grid sync); the host already waits in wait_solving_ends (l.530).
  • Granularity. A deep open node may be tiny; a shallow one huge. Option: sort by depth, or dive a few EPS bits into the biggest items to cut them further.
  • The dive prefix is not on the stack. It must be rebuilt from subproblem_idx (replay the 11-bit dive) or taken from root_store as interval literals.
  • Satisfaction problems. Barebones does not stop at the first solution and its num_solutions is wrong (untyped obj_var, l.1163). Restarts should first be validated on optimization; fix that check separately.
  • Statistics. nodes / fails / subproblems must be summed across rounds; the ENR idle timeline must span all rounds.
